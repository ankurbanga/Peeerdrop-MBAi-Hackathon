# Two-phone demo
1. Open deployed HTTPS Peerdrop on phones A and B. Create distinct names. Pick Marketing Strategy on both cards. B adds industry Healthcare and favorite movie Horror movies. Both explicitly enable mutual-contact graph visibility.
2. A taps Peerdrop, chooses fields, enters Global Hub and creates a QR. B scans with the native camera. Onboarding must return to the invite if B is new.
3. B chooses industry, movies and classes, then requests. A sees B's identity and accepts. Before this final confirmation, selected counterpart details are unavailable.
4. Both open their new connection. A saves “Talked about horror movies” as a private reminder, then optionally creates a separately shared memory. B should see only the shared memory.
5. A searches “healthcare horror”, opens B and sees the shared class/venue. Refresh and confirm persistence.
6. Show the triangle through a fictional contact. Turn B's mutual-contact visibility off and confirm the edge disappears on A's next refresh/poll.
7. Open Events, mark interest, then explicitly share it. Explain this is interest, not an RSVP. Fictional event records have no invented event URLs.

Narrative: “I remember the conversation, but not the name.” Exchange with consent → recall from a fragment → reconnect through context.

Real: hosted persistence, reciprocal consent, immutable selected cards, private/shared notes, deterministic search, current-consent graph and interest signals.
Fictional: seeded people and sample events. No campus imports, no attendance tracking, no proven pilot outcomes.

Before presenting: run hosted database/API integration scripts, rehearse on the actual two phones, verify connectivity, and capture a short backup recording. Browser tests with intercepted APIs are not proof of a real two-phone exchange.
