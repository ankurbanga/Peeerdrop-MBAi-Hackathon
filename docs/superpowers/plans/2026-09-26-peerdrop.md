# Peerdrop Implementation Plan
> Execute inline with bounded lower-cost supporting agents. Existing specification and user build instruction authorize execution.
**Goal:** A mobile prototype with real reciprocal exchange and remembered context.
**Architecture:** Next.js authenticated route handlers use server-only Supabase. Transactional SQL owns exchange state; pure domain helpers own selective cards and retrieval. React client owns browser auth and visible-screen polling.
**Tech Stack:** Next.js, TypeScript, Tailwind, Supabase, React Flow, Zod, Vitest, Playwright.
**Spec:** docs/PRD.md; docs/TECHNICAL_SPEC.md.
## Global constraints
No client table access; no counterpart snapshot before acceptance; no private note leakage; current consent governs graph/event visibility. Real backend required. Fictional fixtures only in DEMO_MODE.
## Review focus
Concurrent accept/request/cancel; forwarded token; hidden fields in responses; stale visibility; mobile overflow and onboarding invite recovery.
